# GitHub Actions

## Текущее состояние

Один workflow — `.github/workflows/update.yml`:
- расписание: `cron: '0 6 * * *'` (06:00 UTC, 09:00 МСК)
- ручной запуск: `workflow_dispatch`
- права: `contents: write` (нужны, чтобы коммитить обновления обратно в репо)
- шаги: checkout → setup-python → install deps → pytest → run scraper → commit & push

## Правила

- **Тесты прогоняются перед скрапером.** Если тесты красные — данные не обновятся, не сломаем `apps.json` багом.
- **Коммит — `chore: daily update <date>`.** Не менять формат, на него может быть завязан changelog.
- **`if git diff --staged --quiet` обязателен** — иначе будут пустые коммиты в дни, когда ничего не изменилось.
- **Время кэшируется через `actions/setup-python` с `cache: 'pip'`** — не убирать, экономит ~30 секунд на запуске.

## Что нельзя коммитить в workflow

- Секреты, токены, ключи. Используется встроенный `GITHUB_TOKEN`, его не нужно объявлять.
- Хардкод username/email — используется бот `github-actions[bot]`.

## Полезные расширения (не реализованы, см. @docs/ROADMAP.md)

- Notification на Slack/Discord/email при падении всех источников.
- Открытие issue при подозрительном изменении (например, добавилось 50 приложений за день — скорее всего парсер сломался и тянет мусор).
- Отдельный workflow для weekly digest — собирает дельту за неделю.

## Дебаг workflow локально

GitHub Actions нельзя запустить полностью локально, но можно прогнать сам скрипт:

```bash
python -m scraper.main
```

Эффект тот же, что в Actions, но без коммита.

Для теста коммит-логики — создай тестовую ветку в форке и пуш-триггер, чтобы не плодить шум в основной истории.
